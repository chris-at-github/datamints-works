# Timesheet Persistence

## Context & Goal

The timesheet is stored in the SQLite database. Two Prisma models are added:
`TimesheetPage` (one day) and `TimesheetEntry` (one table row, linked to a page).
The page loads its entries in the background through a REST API; every blur of a
field saves the entry. Sample data comes from a seed. A "New" button creates a
page for today with five empty rows.

## Non-Goals

- No validation of entry values.
- No reset; the "Reset" button and its logic are removed.
- No deleting or archiving of pages or entries, no clean-up of empty entries.
- No browsing between pages beyond opening `/timesheet/[pageId]` directly.
- No visible save errors; they are only logged to the console.

## Acceptance Criteria

- [x] Two pages with sample data can be loaded.
- [x] Storing the sample data via the seed works.
- [x] Clearing a row works.
- [x] Adding new rows works, and an entry in a new row is saved.
- [x] New rows are still there after a reload.

## Open Decisions

**Models.**
- `TimesheetPage`: `id` (UUID, generated by the application, no database
  default), `date` (text `YYYY-MM-DD`, not unique), `createdAt`.
- `TimesheetEntry`: `id` (UUID from the application), `pageId` (foreign key,
  `onDelete: Cascade`), `sorting` (row order), `startTime`, `endTime`,
  `duration`, `ticket`, `bookingText`, `bookingTextInternal`, all text with
  default `""` so that invalid data can be stored. Index on
  `(pageId, sorting)`.
- The date is text to avoid time zone issues; text in `YYYY-MM-DD` still sorts
  correctly. Rejected: `DateTime`.
- Pages will be archived instead of deleted later; the cascade is only a safety
  net.

**Rename `internalNote` → `bookingTextInternal` everywhere**, including the
column header "Internal booking text".

**Routes.** `/timesheet` loads the latest page, `/timesheet/[pageId]` a given
one. The URL stays `/timesheet` when the latest page is loaded (no redirect).
"New" navigates to `/timesheet/[newId]`, so a reload shows the same page.

**REST endpoints** (route handlers in `src/app/api/`):
- `GET /api/timesheet-pages/latest` → `{ page }`, the page with the highest
  date (ties: newest `createdAt`), including its entries ordered by `sorting`;
  `page` is `null` if there is none.
- `GET /api/timesheet-pages/[id]` → `{ page }` or 404.
- `PUT /api/timesheet-pages/[id]` → creates or updates a page (`date`).
- `PUT /api/timesheet-entries/[id]` → creates or updates an entry (upsert);
  404 if the page does not exist.
- Minimal input check: only string fields are taken, `sorting` must be an
  integer; anything else is ignored or answered with 400.

Rejected: loading in a server component directly via Prisma (simpler, no
loading state), because a background REST request is required.

**Loading.** `Timesheet` fetches the page after mounting and shows a plain
"Loading…" text, or an error text if loading fails. Only the rows from the
database are shown, no padding to five rows. The header shows the page date;
reading today's date via `useSyncExternalStore` is no longer needed.

**No page yet.** If `latest` returns no page, a new page is created
automatically (same as "New"). React Strict Mode runs effects twice in
development; the effect ignores the result of the first, cancelled run, so only
one page is created.

**"New" button** (top right, always visible): generates a page UUID in the
browser, saves the page with today's date, saves five empty entries and then
shows the new page.

**"Add rows".** Five empty entries with browser UUIDs and the next `sorting`
values are added to the state and saved right away with five parallel
`PUT /api/timesheet-entries/[id]` calls, so they exist after a reload. Rejected:
a batch endpoint (one more endpoint, not needed yet).

**Saving on blur.** Every blur of any field saves the whole entry, also for
empty rows (they already exist in the database). Time fields are completed and
rounded first, then saved. Errors are logged to the console.

**Seed.** `prisma/seed.ts` creates two pages on fixed days: the newer one with
eight entries (to show more than five rows), the older one with three. Run via
`prisma db seed` (configured in `prisma.config.ts`) with `tsx`, because the
generated client uses extensionless imports that Node's own TypeScript support
cannot resolve. The seed clears both tables first, so it can be run again.

**`db:migrate` also generates the client.** Since Prisma 7, `migrate dev` no
longer runs `generate`, so the seed failed with an outdated client. A
`postdb:migrate` hook runs `prisma generate` afterwards. Rejected:
`prisma migrate dev && prisma generate`, because npm appends arguments like
`-- --name …` to the last command.

**Data access in `src/lib/timesheet-repository.ts`.** Route handlers stay thin;
the repository shapes rows like the API response (entries ordered, without
`pageId`). The shared types (`TimesheetEntry`, `TimesheetPageData`,
`TimesheetValues`) live in `src/modules/Timesheet/entries.ts` and are used by
client and server. `src/lib/request.ts` reads a JSON body or returns null for
a 400.

**Name clash.** Prisma generates the types `TimesheetPage` and `TimesheetEntry`,
same as the component and the client type. Route handlers import Prisma types
under aliases where needed.
